# Evidence Lab

Build a complete responsive web application called:

Learning Evidence & Experiment Studio

Tagline:

Test the learning strategy. Challenge the assumptions. Design the evidence.

This is a professional portfolio-grade interactive product created to demonstrate senior-level expertise in learning strategy, research, measurement, experimentation, evidence-based decision making, and responsible use of AI.

This is NOT:

a generic AI chatbot

an LMS

a training course catalog

an analytics dashboard

a startup landing-page cliché

an academic research website

It should feel like a sophisticated interactive decision studio designed for senior L&D leaders, talent leaders, research leaders, organizational effectiveness professionals, HR leaders, product leaders, and executives.

The intended secondary audience is hiring managers and recruiters evaluating the creator’s strategic thinking, research rigor, product sense, communication skill, and visual taste.

STUDIO WORKFLOW

The main application must contain six connected experiences.

Use a persistent but elegant progress indicator.

Do not make it resemble a tax form or generic wizard.

The experiences are:

1 — Learner Context

Headline:

Who has to perform differently?

Collect:

Role

Tenure

Prior knowledge

Current skill level

Task complexity

Motivation

Confidence

Time available for learning

Workload

Manager support

Opportunity to practice

Frequency of task performance

Environmental or access constraints

Do NOT use “learning styles.”

Allow users to create between one and three learner context profiles.

Provide an optional example profile.

Example:

Experienced but constrained

Strong prior knowledge and motivation, but limited protected learning time and inconsistent manager reinforcement.

The app should explain:

These profiles are structured scenarios used to examine how context may affect a learning strategy. They are not predictions of individual human behavior.



2 — Intervention Builder

Headline:

Allow users to construct a learning intervention from components.

Components:

Simulation

Practice with feedback

Job aid

Manager coaching

Performance support

Follow-up assessment

Reinforcement nudge

Each component should be represented visually and be reorderable.

Collect:

estimated learner time

frequency

practice opportunity

Show the intervention as a horizontal or vertical journey.

Performance check



3 — Experiment Sandbox

Headline:

What changes if we design it differently?

Allow the user to create:

Scenario A — Current Approach

Scenario B — Alternative Approach

Optional:
Scenario C — Lean Alternative

Allow users to modify intervention components.

Compare scenarios across:

expected retention support

practice quality

opportunity for transfer

manager burden

learner time

implementation effort

measurement quality

scalability

evidence confidence

IMPORTANT:

Do NOT fabricate precise causal effects.

Do NOT claim:

“Retention will increase 23%.”

Instead use directional outcomes such as:

Stronger support

Likely improvement

Similar

Potential tradeoff

Unknown

Insufficient evidence

For every directional assessment provide a concise explanation.

Example:

Retention support — Likely stronger

The alternative introduces spaced retrieval and repeated practice rather than relying on a single exposure.

Unknown

Generate a clear statement such as:

Your current measurement strategy can tell you whether people completed and liked the program. It cannot yet establish whether they learned, changed behavior, or improved performance.

Never imply that satisfaction proves learning.

Never imply that confidence proves competence.

Never imply that correlation proves causation.



5 — Pilot & Calibration

Headline:

Turn the assumption into something testable.

Create a simple pilot design builder.

Collect:

target population

sample/cohort description

intervention condition

comparison condition if appropriate

baseline measure

immediate measure

delayed measure

transfer measure

performance measure

follow-up timing

Show:

BEFORE PILOT

What we expect

AFTER PILOT

What we observed

CALIBRATION

What changed in our understanding

Include a sample demonstration where:

Expectation:
Manager coaching should improve transfer.

Observation:
Managers participated inconsistently.

Calibration:
The mechanism may be sound, but implementation capacity became the limiting condition.

Next experiment:
Test structured peer reinforcement against manager-dependent reinforcement.

Do not claim a pilot proves causality unless the study design supports that conclusion.

SKEPTICAL CFO FEATURE

On the Executive Decision Brief include a distinctive secondary button:

Challenge This Recommendation

When selected, open a panel called:

The Skeptical Review

The tool should deliberately argue against the recommendation.

Evaluate:

Is this actually a learning problem?

Could workflow or system design be responsible?

Could incentives explain the behavior?

Could manager capability be the constraint?

Is there a cheaper intervention?

Does evidence establish the claimed problem?

Are we solving a symptom?

What assumption carries the greatest risk?

Example output:

Reason to pause

The available evidence establishes low adoption but does not establish a skill deficit.

Alternative explanation

Workflow friction or low perceived usefulness may explain the behavior.

Lower-cost test

Conduct targeted workflow observation before redesigning the learning program.

This feature should feel rigorous, not gimmicky.



EVIDENCE LABELING SYSTEM

Every major conclusion throughout the application must use one of four labels:

EVIDENCE-BACKED

Supported by evidence entered into the assessment or an established design principle.

MODEL ASSUMPTION

A reasonable assumption used to compare scenarios.

USER ASSUMPTION

Something entered by the practitioner that has not been independently verified.

HYPOTHESIS

A plausible explanation worth investigating but not yet evidence.

Use understated visual treatments.

Do not use giant badges everywhere.
